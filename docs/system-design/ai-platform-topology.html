A-Game · AI platform layer · ADR 0008

The platform around the models — gateway, tracing, evals, orchestration

The daily pipeline is designed to predict (Elo + Poisson) and narrate (Claude Haiku, falling back to OpenAI) — as of 2026-08-05 neither is built yet; handlers.py is a stub, and the second provider route is specified but not applied. This layer wraps the LLM call in the operational surface an AI platform needs: one controlled egress hop, per-request cost/latency tracing, retrieval grounding, and DAG orchestration — all as ordinary private-subnet workloads. The numbers being predicted don't change. Re-weighted 2026-08-05: the CI eval gate is the layer's flagship deliverable (golden dataset, fact-checker, LLM-as-judge, regression block), with a model-comparison report, a tool-using agent, and a self-hosted CPU-scale third route added behind it — decided, not drawn here yet.

One preview, end to end

  1. 1The daily scheduler (06:00 UTC — CronJob today, Argo in Tier 2) runs the worker. If the upsert changed anything (ADR 0007) it publishes a "data ready" event; the brain consumer reacts off RabbitMQ and recomputes Elo + Poisson. Brain is never run on a timer.
  2. 2commentary.py — a module inside the brain pod, not a service of its own — builds the prompt, and (Tier 2) pulls similar historical matches from pgvector to ground it.
  3. 3It calls the LiteLLM gateway at its cluster-internal Service address, asking for the alias claude-haiku — not a provider directly. The gateway checks the budget, tries the cache, and holds the only credentials.
  4. 4On a cache miss the gateway makes the one egress call on :443 — to api.anthropic.com, or to api.openai.com if the primary route fails and the configured fallback engages. Either way it is the single pod-to-internet hop the NetworkPolicy has to allow, and the caller never learns which provider answered.
  5. 5The gateway emits a trace to Langfuse — tokens, cost, latency, prompt, response, model version — then returns the preview.
  6. 6The preview lands in Postgres (model-versioned) and warms Redis; FastAPI serves it later as a plain read.
  7. 7Separately, CI runs the eval harness on every change and blocks the merge if output quality regresses.

Why the gateway is the centerpiece. Routing every LLM call through one pod means the blast radius of the provider credentials and the egress path is a single workload — the NetworkPolicy allows external :443 from the gateway only, and IRSA scopes the Secrets to the gateway's ServiceAccount alone. Since 2026-08-04 that pod holds two providers' keys, with Claude Haiku falling back to OpenAI: one workload still, but a wider secret. The egress rule is 0.0.0.0/0:443 rather than provider CIDRs — both sit behind rotating CDN ranges — so the enforced boundary is which pod may leave, not where it may go.
Not drawn: GPU serving (Tier 3). Self-hosted vLLM / KServe on a GPU node group is designed in ADR 0008 but stays document-only — the accent here is that the whole platform runs on ordinary CPU workloads at ~$0 locally.
Argo is an open fork (Tier 2). Either it replaces only the daily worker scheduler — brain stays a RabbitMQ consumer — or it models the whole pipeline as a DAG and RabbitMQ drops its trigger role. Not both, and brain is never triggered on a timer. Defaulting toward the first.
Sequencing (revised 2026-07-30). This layer now lands first, ahead of the EKS-portability and app-correctness tracks — ADR 0009 made the EKS cluster layer plan-only, so waiting on the infra track would mean waiting forever. Tier 1 depends on no applied AWS resource. Build order (revised 2026-08-05): gateway → Langfuse → eval gate (flagship) → comparison report → threat-model doc + budget alerts → pgvector (with retrieval evals) → agent → self-hosted route → Argo.
No new Python services. Tier 1 adds five workloads (LiteLLM, langfuse-web, langfuse-worker, ClickHouse, MinIO) and every one is an off-the-shelf image. The only Python written is commentary.py plus edits to handlers.py / config.py, all inside the existing brain service, and the eval fixtures in CI.
